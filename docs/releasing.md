# 译伴输入法发布建议

项目中文名为 **译伴输入法**，英文名为 **Yiban IME**，仓库为 [billylu24/Yiban-IME](https://github.com/billylu24/Yiban-IME)。名称表达的是中文输入时的英文辅助；没有进行商标或仓库名称可用性检索。内部兼容标识继续保留，不要求现有用户迁移 Rime 用户数据库。

## 建议发布顺序

| 平台 | 用途 | 建议时机 |
|---|---|---|
| GitHub 仓库 | 源码、Issues、贡献与持续集成的主入口 | 第一站 |
| GitHub Releases | 固定版本源码、变更说明、环境要求和校验值 | 首个预览版 |
| Rime / Fcitx 社区的交流渠道 | 收集输入兼容性反馈，讨论上游补丁维护 | 能提供最小复现和清晰安装说明时 |
| V2EX「分享创造」、Linux 用户社区 | 寻找真实桌面用户试用 | 有演示视频、支持范围和回退说明时 |
| 掘金、知乎、B 站 | 中文功能介绍、开发过程与使用演示 | 首发后 |
| Codeberg / Gitee 镜像 | 提供备用代码入口 | 主仓库稳定后，明确唯一 issue 入口 |
| AUR、deb/rpm 或发行版仓库 | 降低安装成本 | 有稳定版本、许可证和维护能力后 |

以上是建议，不代表项目已发布或已被这些社区接纳。社区发帖遵守其具体版规；不要把 issue 跟踪器当广告区。Fcitx 与 Rime 的讨论应聚焦兼容性和补丁设计。

## 首发内容

建议首版使用 `v0.1.0-preview.1` 之类的预览标识，明确支持的发行版、架构和 Fcitx 版本。附带：

- 一段简短演示：候选英文词义 → 句子翻译 → 空格隐藏 → 光标返回恢复 → 原句修改更新。
- 源码安装方法、统一配置样例、关闭整句翻译的步骤。
- 本次构建使用的上游 SHA、雾凇 commit、模型名称及实际 Ollama 模型摘要。
- 测试结果、已知限制、更新和卸载说明。
- 出问题时应提供的信息：发行版、桌面、X11/Wayland、应用、Fcitx 版本、可脱敏的复现步骤。

不要将整个 `.local-env`、个人配置、用户词库、日志或模型权重直接压缩上传为发布包。模型通过 Ollama 另行获取，避免巨型安装包和模糊的数据授权。

## 发布前尚需完成

1. **选择源码许可证。** 当前没有顶层 LICENSE。考虑与上游补丁协作及分发方式后决定；可评估 GPL-3.0-or-later，但应先核对实际包含的代码与第三方条件。CC-CEDICT 数据许可需要单独保留。
2. **核对源码完整性。** 发布 commit 必须包含 `src/addon`、`src/context`、`src/translation`、`translator`、`tools`、`data`、配置和新增测试。
3. **从干净克隆验证。** 不能把开发机 `.local-env` 的存在当成依赖已解决；至少在一台干净机器按 README 构建。
4. **补桌面兼容矩阵。** 至少覆盖 GTK、Qt、浏览器、终端，记录各自 surrounding text 的支持情况。
5. **固定词库与模型。** 记录实际版本，不仅写 `main` 或可变模型 tag。
6. **如分发二进制，按目标系统打包。** 检查 libdir、ABI、第三方许可与包管理器卸载流程，并发布 SHA-256 校验值。

目前更适合先邀请少量 Linux/Rime 用户试用，收集光标行为与模型延迟反馈，再投入多发行版包维护。
